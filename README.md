# SplitUp · หารกัน

แอปภาษาไทยสำหรับหารค่าใช้จ่ายกับเพื่อนในทริปหรือกิจกรรมร่วมกัน บันทึกว่าใครจ่าย ใครร่วมหาร และใครต้องโอนคืนให้ใคร พร้อมเก็บข้อมูลในอุปกรณ์และแชร์สรุปได้

พัฒนาต่อจาก SplitExpense โดยแปลงจาก Next.js มาเป็น **Expo SDK 57 / React Native** สำหรับ Android, iOS และเว็บ

## ฟีเจอร์

- **จัดการทริป** — สร้างทริปพร้อมวันที่และสมาชิก สลับดูทริปย้อนหลัง
- **จัดการค่าใช้จ่าย** — เพิ่ม ดู แก้ไข ลบ ค้นหา และกรองตามหมวดหมู่
- **หารเงิน 3 แบบ** — หารเท่ากัน กำหนดยอดแต่ละคน หรือกำหนดเปอร์เซ็นต์
- **สรุปยอด** — ดูยอดที่จ่ายไป ค่าใช้จ่ายจริง และยอดคงเหลือของแต่ละคน
- **แนะนำการโอน** — แสดงผู้โอน ผู้รับ และจำนวนเงิน พร้อมบันทึกหรือยกเลิกสถานะชำระแล้ว
- **จัดการสมาชิก** — เพิ่มและแก้ไขชื่อ ลบสมาชิกที่ไม่มีรายการเกี่ยวข้อง
- **แชร์สรุป** — แชร์ผ่านเมนูของมือถือ หรือคัดลอกข้อความไปส่งต่อ
- **สำรองและนำเข้า** — คัดลอกข้อมูลทั้งหมดเป็น JSON และนำเข้าข้ามอุปกรณ์
- **ปรับตามขนาดจอ** — เมนูด้านล่างบนมือถือ เมนูด้านข้างบนจอกว้าง และฟอร์มที่ปรับขนาดอัตโนมัติ

แอปเริ่มต้นโดยไม่มีทริปตัวอย่าง ไม่ต้องสมัครบัญชีหรือตั้งค่าฐานข้อมูล

## เริ่มใช้งานสำหรับนักพัฒนา

### สิ่งที่ต้องมี

- Node.js 22.18 ขึ้นไปสำหรับคำสั่งทดสอบที่อ่าน TypeScript โดยตรง; โปรเจกต์นี้ผ่านการตรวจด้วย Node.js 24.19
- npm
- เบราว์เซอร์สำหรับรันเว็บ
- Expo Go ที่รองรับ SDK 57 หรือ development build สำหรับทดสอบบนมือถือ
- Google Chrome สำหรับชุดทดสอบเบราว์เซอร์

### ติดตั้งและรัน

เปิด Terminal ในโฟลเดอร์โปรเจกต์:

```sh
npm ci
npm start
```

เลือกแพลตฟอร์มจาก Expo CLI หรือใช้คำสั่ง:

| คำสั่ง            | การใช้งาน                                   |
| ----------------- | ------------------------------------------- |
| `npm run web`     | เปิดแอปบนเว็บ                               |
| `npm run android` | เริ่ม Expo และเปิดบน Android ที่เตรียมไว้   |
| `npm run ios`     | เริ่ม Expo และเปิดบน iOS Simulator บน macOS |

สำหรับมือถือจริง ให้เปิดแอปผ่าน Expo Go หรือ development build ตามสภาพแวดล้อมที่ใช้ การรัน iOS Simulator และ build iOS ในเครื่องต้องใช้ macOS พร้อม Xcode

เวอร์ชันปัจจุบันไม่ต้องมีไฟล์ `.env` หรือ API key

## วิธีใช้งานแอป

1. เปิดแอป แล้วเลือก **สร้างทริป**
2. กรอกชื่อทริป วันที่ในรูปแบบ `YYYY-MM-DD` และชื่อสมาชิกอย่างน้อย 1 คน
3. เลือก **เพิ่มค่าใช้จ่าย** ระบุจำนวนเงิน ชื่อรายการ หมวดหมู่ วันที่ และคนจ่าย
4. เลือกคนร่วมหารและรูปแบบการหาร แล้วบันทึก
5. เปิด **สรุปยอด** เพื่อดูยอดของแต่ละคนและรายการที่ต้องโอน
6. เมื่อโอนเงินจริงแล้ว เลือก **บันทึกว่าชำระแล้ว**
7. ใช้ **แชร์สรุป** เพื่อส่งรายละเอียดให้เพื่อน

การบันทึกว่าชำระแล้วเป็นการลงประวัติในแอป ไม่มีการโอนเงินหรือเชื่อมต่อธนาคาร

## การเก็บข้อมูล

แอปเก็บข้อมูลด้วย AsyncStorage โดยใช้คีย์ `harnkan-trips-v1` บนเว็บข้อมูลอยู่ใน localStorage ของเว็บไซต์นั้น

- ข้อมูลคงอยู่หลังปิดและเปิดแอป แต่ไม่ซิงก์ระหว่างอุปกรณ์หรือเบราว์เซอร์
- การล้างข้อมูลแอป ล้างข้อมูลเว็บไซต์ หรือถอนการติดตั้งอาจทำให้ข้อมูลหาย
- AsyncStorage ไม่ใช่พื้นที่เก็บข้อมูลเข้ารหัส
- เมื่อเปิดแอป ทริปตัวอย่างเดิมที่ตรงกับค่าเริ่มต้นทุกประการจะถูกนำออก ส่วนทริปที่แก้ไขหรือสร้างเองจะถูกเก็บไว้
- ข้อมูลตัวอย่างในโค้ดยังคงใช้กับการทดสอบและการตรวจทริปตัวอย่างเดิม โดยไม่เพิ่มเข้าแอปเมื่อเริ่มใช้งาน

### สำรองข้อมูล

1. เปิด **สำรอง / ย้ายข้อมูล**
2. เลือก **คัดลอกข้อมูลทั้งหมด (JSON)**
3. วางข้อความลงในไฟล์ `.json` และเก็บไว้สำหรับกู้คืนหรือย้ายอุปกรณ์

### นำเข้าข้อมูล

1. เปิด **สำรอง / ย้ายข้อมูล** ในอุปกรณ์ปลายทาง
2. วาง JSON ที่สำรองไว้
3. เลือก **ตรวจสอบและนำเข้า** แล้วยืนยัน

**การนำเข้าจะแทนที่ทริปทั้งหมดในอุปกรณ์ปลายทาง** ไม่ใช่การรวมข้อมูล ควรสำรองข้อมูลเดิมก่อนนำเข้า

### ย้ายจาก SplitExpense

เปิดเว็บ SplitExpense เดิม ใน Chrome DevTools Console ใช้:

```js
copy(localStorage.getItem("harnkan-trips-v1"));
```

จากนั้นนำ JSON ไปวางในหน้าสำรอง / ย้ายข้อมูลของ SplitUp หากเว็บเดิมใช้ PostgreSQL ให้รอซิงก์ข้อมูลล่าสุดก่อนคัดลอก

`copy()` เป็นคำสั่งของ DevTools ข้อมูลจะไม่ย้ายข้ามเว็บไซต์หรือเข้าแอปมือถือโดยอัตโนมัติ

## หลักการคำนวณ

ระบบคำนวณอยู่ใน [src/lib/engine.ts](./src/lib/engine.ts)

- เงินเก็บเป็นจำนวนเต็มหน่วย **สตางค์** เช่น 125.50 บาท เก็บเป็น `12550`
- หารเท่ากันจะกระจายเศษสตางค์ตามลำดับผู้ร่วมรายการ
- กำหนดยอดต้องมีผลรวมตรงกับค่าใช้จ่าย
- กำหนดเปอร์เซ็นต์ต้องรวมเป็น 100% และกระจายเศษด้วยวิธี largest remainder
- แนะนำการโอนโดยจับคู่ยอดตรงกันก่อน แล้วจับคู่ยอดคงเหลือที่มากที่สุด วิธีนี้ไม่รับประกันจำนวนการโอนต่ำที่สุดสำหรับทุกกรณี
- ประวัติการชำระเก็บแยกจากค่าใช้จ่าย เมื่อแก้ไขหรือลบรายการ ระบบจะคำนวณยอดคงเหลือใหม่โดยยังเก็บเงินที่โอนไปแล้ว

ข้อมูลปัจจุบันรองรับสกุลเงินบาท (THB) เท่านั้น

## โครงสร้างโค้ดหลัก

```text
src/
├── app/
│   ├── _layout.tsx           # โหลดฟอนต์และตั้งค่า Expo Router
│   ├── index.tsx             # สถานะแอป การบันทึกข้อมูล และการทำงานของหน้าจอ
│   └── explore.tsx           # เปลี่ยนเส้นทางกลับหน้าหลัก
├── components/
│   ├── split-dashboard.tsx   # โครงหน้าจอ เมนู และภาพรวมแบบ responsive
│   ├── split-forms.tsx       # ฟอร์มสร้างทริปและเพิ่ม/แก้ไขค่าใช้จ่าย
│   └── split-ui.tsx          # ปุ่ม ช่องกรอก การ์ด หน้าต่าง ฟอนต์ สี และไอคอน
└── lib/
    └── engine.ts             # ชนิดข้อมูล ตรวจสอบข้อมูล หารเงิน และสรุปยอด
scripts/
└── browser-test.cjs          # ทดสอบการใช้งานเว็บและขนาดหน้าจอ
tests/
└── engine.test.mts           # ทดสอบระบบคำนวณ
```

ยังมีไฟล์จาก Expo starter อยู่ในโปรเจกต์ ตารางข้างต้นแสดงเฉพาะส่วนหลักของ SplitUp

## ตรวจสอบและทดสอบ

### TypeScript และระบบคำนวณ

```sh
npm run typecheck
npm test
```

ชุดทดสอบคำนวณครอบคลุมยอดจ่ายและส่วนแบ่ง เศษสตางค์ ข้อมูลที่ไม่ถูกต้อง การแก้ไขหลังชำระเงิน และการคงยอดรวมของเงิน

### ทดสอบบนเบราว์เซอร์

ต้องติดตั้ง Google Chrome ในเครื่อง และสร้างเว็บจากโค้ดล่าสุดก่อนรัน:

```sh
npx expo export --platform web
npm run test:browser
```

สคริปต์เปิดเซิร์ฟเวอร์ทดสอบและ Chrome แบบ headless ให้อัตโนมัติ ใช้ข้อมูลทดสอบในบริบทเบราว์เซอร์แยกจากข้อมูลใช้งานจริง

ครอบคลุมการเริ่มต้นว่าง การนำทริปตัวอย่างเดิมออก การเก็บข้อมูลที่แก้ไขไว้ การจัดการรายการ การบันทึกข้ามการรีโหลด การชำระและยกเลิก รวมถึงเลย์เอาต์กว้าง 320, 390, 768, 1024 และ 1440 พิกเซล ตลอดจนชื่อยาวและยอดเงินจำนวนมาก

ภาพหน้าจอจากการทดสอบอยู่ใน `dist/review/` และอาจถูกแทนที่เมื่อ export หรือรันทดสอบใหม่

### ตรวจบันเดิลทุกแพลตฟอร์ม

```sh
npx expo export --platform all
```

ผลลัพธ์อยู่ใน `dist/` คำสั่งนี้สร้างบันเดิล JavaScript และ assets ไม่ได้สร้างไฟล์ติดตั้ง APK, AAB หรือ IPA และไม่แทนการทดสอบบนมือถือจริง

### จัดรูปแบบโค้ด

```sh
npm run format
```

คำสั่งเสริมจาก starter:

- `npm run lint` เรียก Expo lint; ยังไม่มี ESLint ใน devDependencies และอาจมีขั้นตอนตั้งค่าเพิ่มเติม
- `npm run reset-project` ใช้รีเซ็ตซอร์สของ starter โดยย้ายหรือลบ `src/` และ `scripts/` ไม่ใช่คำสั่งล้างข้อมูลทริป

## ขอบเขตปัจจุบัน

- เก็บข้อมูลเฉพาะอุปกรณ์ ยังไม่เชื่อม API หรือ PostgreSQL ของ SplitExpense
- ยังไม่มีล็อกอิน การเชิญเพื่อน หรือแก้ไขข้อมูลร่วมกันหลายคน
- ยังไม่มีการแนบใบเสร็จ OCR, QR PromptPay หรือส่งออก PDF/Excel
- UI หลักเป็นธีมสว่าง และแอป native ตั้งค่าการแสดงผลแนวตั้ง
- มีการตรวจบันเดิล Android/iOS และทดสอบการใช้งานบนเว็บ แต่ยังต้องทดสอบบนอุปกรณ์จริงก่อนเผยแพร่
